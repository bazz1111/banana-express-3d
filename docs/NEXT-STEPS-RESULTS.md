## 美术与验收仍未完成

六红岩模块、三个景深带及其山/云变体、宽海面、沿岸六处聚落、核心钟楼/广场已在 Blender 重建；路面、中心线、标线、护栏数据保持不变，所有岩脚和建筑完整占地支撑检查通过。核心聚落49屋、近景共131建筑，远坡建筑数量见最终规范源；森林2400树、远景3600树与160棕榈。

实际图片仍有差距，不能用原生模型数量代替图A视觉验收。保留原27样本和原门槛的美术检查仍报告失败：

- 海湾在代表弯道可见，近岸下降与森林开窗改善遮挡，但左上象限最大覆盖约3.82%，尚低于建议30%。
- 竖屏百万米夹具的蓝色山带覆盖约0.546%，低于1.15%的原门槛；资源和周期连续性通过，不等于画面构图通过。
- 少数宽屏转弯样本城镇覆盖不足0.4%；森林覆盖已超过2.5%门槛。城镇核心存在，也不等于每个视角都可读。
- 人物已有新的网格、权重和动作，面部、衣褶及蕉堆轮廓仍需对照独立美术参考打磨。

六张角色正交图与三张布局/颜色/光照SVG进入 [参考索引](../assets/reference/README.md)。它们明确标为当前实现草稿，角色为自行车支撑绑定姿势而非A-pose；12类素材并未全部由用户确认。当前实现渲染不能反过来作为“已经严格还原”的独立证明。

GTX1650、IrisXe、iPhone、Android及Safari真机未在本轮获得。Apple M6上的Chrome数据只证明该机器的情况；没有把软件WebGL、虚拟时钟或盾保活夹具冒充中端电脑/手机自然跑局。显存峰值也未由GPU工具测量。

## 实际验证证据

Apple M6、Chrome155、1920×1080、有头窗口、5秒预热、每档3次60秒的实际rAF采样如下。取帧时中位数，绘制预算列取三轮峰值；显示刷新约180Hz。

| 指标 | 改前高档 | 改后高档 | 改前低档 | 最终低档 |
|---|---:|---:|---:|---:|
| p50 / p95 / p99，ms | 5.6 / 6.5 / 6.8 | 5.6 / 6.5 / 6.8 | 5.6 / 6.3 / 6.7 | 5.6 / 6.0 / 6.2 |
| 整帧最大GL调用 | 150 | 183 | 107 | 123 |
| 整帧最大绘制三角面 | 2,534,546 | 1,397,974 | 1,944,801 | 794,621 |
| 首屏资源传输，MiB | 20.726 | 5.515 | 20.726 | 5.515 |

新卡车分件及景深组增加了调用数，仍低于300/220预算；面数下降约45%/59%。M6上帧率接近显示刷新上限，不能宣称FPS同比大幅提升。最后一次修改只将低档森林密度从50%改为45%，高档代码路径和原生资产未改变；高档保留修改前的三轮测量，低档按最终配置重测三轮。JSON逐轮记录实际脚本文件名。

最终低档三轮最长帧为60.8、27.8、6.3ms；中间配置的一轮还观察到791ms停顿，当时同时准备Git文件，单凭rAF无法确认原因。全部保留，没有过滤掉这些帧。p95/p99通过本机帧时预算，不构成对所有设备或每一帧都稳定60FPS的保证。[精简测量及中间轮记录](../verification/next-perf-apple-m6.json)。

- 本地94项单元测试、TypeScript检查、生产构建、60资产检查、无损比较通过。
- 两次独立全量Blender重建、严格指纹，以及全部10个只读原生检查通过。
- 实际Chrome键盘跑局超过2500m，自然拾127蕉、踢两辆重卡，三道具、跳跃、坐站、暂停、主动/碰撞结束和重开通过，0页面/资源错误；虚拟时钟用于加快功能回归，不能推断FPS。峰值208整帧GL调用、约1.434M绘制三角面。
- 两竖屏真实持续触控冒烟通过；WebGL丢失/恢复、长数字HUD、百万米相对原点和周期支撑验证通过。
- 修复后的音效首次加载25次、缓存25样本、单AudioContext，同类10次拾取保留4声部；结算约605ms与碰撞约1014ms尾音自然结束。

`verification/` 保存选择的图片及精简报告；完整原始日志/帧样本保留在本机 `artifacts/`。改前后图片采用同一冻结200m/85蕉夹具，明确不作为玩家成绩；未宣称截图像素完全相同。远端CI状态以PR实际结果为准。

PR #3的首轮Linux x64原生重建通过路面/护栏和支撑检查，但赛道JSON出现32个朝向尾数差异，最大2.22e-16；另有23个GLB的浮点值、导出排列或由它们生成的AO几何哈希不同。下载产物后逐文件确认，不能只删除失败的赛道哈希检查。原生流水线改为与作者平台一致的macOS ARM64，并继续固定官方Blender版本、下载SHA256和原有精确指纹；Linux仍验证已提交运行资产的指纹、压缩等价、构建及浏览器行为。模型和游戏代码未因这次CI调整改变。跨操作系统/架构的字节复现仍不在保证范围内；[比对记录](../verification/next-native-platform-report.json)保存首轮失败与诊断证据。

第二轮macOS ARM64重建CI已通过。首轮Chromium触控冒烟还发现测试临时卡车被异步输入调用越过的时序问题；真实触控松手延迟1.2秒的回归能复现旧脚本踢空。修复为仅在临时飞踢夹具中冻结位置，真实keyup/touchEnd送达后恢复正常规则，仍要求卡车被踢中且本局继续。相同延迟回归通过，高档保持本地默认。软件GL的CI冒烟显式使用运行低档，报告记录档位及夹具冻结，不将其帧时冒充实机性能。详见[输入延迟回归](../verification/next-smoke-latency-report.json)。

未纳入本轮的完整烘焙lightmap、KTX2、后期Bloom、在线排行、完整轮胎物理和付费真机服务属于后续投入，不应当作已经实施。
